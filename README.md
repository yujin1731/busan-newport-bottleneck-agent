# 신항 병목 관제 v4-twin (시연용)

부산신항 3D 디지털트윈 위에서 담당자가 4단계를 거친다.
S1 관제 → S2 진단 → S3 대응 시뮬레이션 → S4 승인. 화면은 승인에서 끝나며 실제 공문·장비 제어는 없다.

## 실행

```
npm install
npm run dev        # http://localhost:5177
npm run build      # dist/
node scripts/gen-mock.mjs   # mock JSON 다시 만들기
```

## 데이터

모든 수치는 가상 시나리오(시연값)다. 화면에는 시연 표기를 두지 않으므로 발표·보고서에서 가상 시나리오임을 밝힌다.
데이터 접근은 `src/data/dataSource.ts` 한 파일에 있다. API로 바꿀 때는 이 파일만 고친다.

| 파일 | 내용 | 단위·출처 |
| --- | --- | --- |
| `layout.json` | 터미널(경도·위도 상자, 안벽 방향, 블록), 도로 노드·링크, 육지, CCTV 위치 | 장면 1 = 10 m. BCT·BNCT·HPNT 위치는 추정 |
| `state_{h}.json` | h = -24..0 시간. KPI, 블록 장치율, 게이트(대기 대, TAT 분, 처리 대/시), 링크 속도(km/h), 선박 수 | 출처 유형 `실측`·`추정` 표기 |
| `alerts.json` | 경보 id, 심각도, 위치 노드, 지속시간 | |
| `diagnosis.json` | 혼잡 위치, 원인 블록, 확신도, 근거 3개(값, 평소 범위, 12시간 추이), 영상 후보 점수 | 영상 점수는 후보일 뿐 판정 아님 |
| `action.json` | 조치 유형, 물량(TEU), 출발·도착, 경로 노드, 제약, AI 설명 3줄, 협의 대상 | |
| `sim_before.json`, `sim_after.json` | 10분 단위 37단계(6시간): 게이트 대기열, 누적 이동 TEU | `시뮬` |
| `result.json` | 결과 4개(값, 범위) | `시뮬`, 조치 안 함 대비 6시간 합계 |

차량번호·컨테이너번호 같은 식별 정보는 어떤 파일에도 없다.

## 화면 규칙

- 색: 회색 = 정상, 주황 = 주의·혼잡 전가(점멸), 빨강 = 병목(혼잡 위치는 바닥 면, 원인은 링·핀, 전파는 점선 화살표), 파랑 = 대응.
- 컨테이너는 블록 장치율에 따라 단(최대 5단)으로 쌓인다. 한 상자는 실제보다 약 2배 크게 그렸다.
